# 채팅 출처 기반 답변과 자동 문서 참조 설계

## 결정

채팅을 열거나 질문을 보내는 시점을 RAG 런타임의 명시적 온디맨드 진입점으로 삼는다. 플러그인 시작은 계속 가볍게 유지하되, 채팅에서는 기존 IndexedDB 인덱스를 자동으로 준비하고 질문과 가까운 볼트 문서를 MCP 없이 첨부한다. 질문에 볼트 폴더 이름이 자연어로 드러나면 해당 폴더를 검색 범위 힌트로 사용하고, 명시적 폴더 멘션은 RAG와 같은 파일 형식을 읽는다.

채팅 화면은 `현재 할 일 → 대화 → 자동 문서 참조 상태 → 입력` 흐름으로 정리한다. 정상 상태와 정상 MCP 연결은 조용히 숨기고, 사용자가 행동해야 하는 상태만 한 문장과 하나의 행동으로 보여준다.

사용자는 이번 작업에 대해 반복 승인 없이 자율 진행을 명시했다. 따라서 이 문서는 구현 계약으로 바로 사용한다.

## 근거

- 테스트 볼트에는 2,107개 문서와 43,680개 벡터가 정상 저장되어 있었지만, 채팅 시작 시 `ragEngine`이 `null`이라 자동 컨텍스트가 비어 있었다.
- 대형 볼트 시작 크래시 방지를 위해 eager RAG 초기화를 제거한 뒤 채팅 전송이 온디맨드 초기화 경로에 포함되지 않았다.
- `RAG 준비 안 됨` 행동은 런타임만 준비한 뒤 실제 pending indexing을 시작하지 않았다.
- 저장된 대화에는 출처 0개 응답, 무관한 Context7 호출, reasoning을 사용자 질문으로 노출한 뒤 tool call을 중단한 기록, 실제 볼트에 없는 구조를 생성한 응답이 남아 있다.
- RAG는 `.txt`를 인덱싱하지만 폴더 멘션은 `getMarkdownFiles()`만 사용해 `neville/*.txt`를 모두 제외했다.
- 현재 빈 대화 화면은 자동 문서 참조가 기본 동작이라는 사실과 예시 질문을 설명하지 않는다.

## 검토한 접근

1. **표면 정리만 수행**: 위험은 작지만 RAG 런타임 단절, 잘못된 MCP 선택, 무출처 응답을 해결하지 못한다.
2. **권장안 — 채팅 온디맨드 RAG + 범위 힌트 + 근거 상태 UI**: 시작 성능을 보존하면서 채팅에서 필요한 기능을 자동으로 준비하고, 내장 문서 참조를 기본 경험으로 만든다.
3. **플러그인 시작 시 eager RAG 복원**: 구현은 단순하지만 과거 대형 볼트 렌더러 크래시를 재발시킬 수 있다.

2안을 적용한다.

## 런타임 흐름

1. 채팅 뷰가 열리면 RAG 런타임 준비를 비동기로 시작한다.
2. 사용자가 먼저 전송하더라도 prompt context를 만들기 전에 같은 coalesced 초기화 작업을 기다린다.
3. 기존 IndexedDB 인덱스가 있으면 즉시 검색에 사용한다. 인덱스가 비었거나 stale이면 background pending indexing을 시작하고 상태를 채팅에 반영한다.
4. 질문은 기본 전역 RAG 검색을 수행한다.
5. 질문 토큰과 최상위 볼트 폴더 이름이 직접 또는 한글 로마자 표기와 유사하게 맞으면 해당 폴더 prefix로 제한한 보조 검색을 수행한다.
6. 전역 결과와 범위 검색 결과를 중복 제거한 뒤 기존 출처 검증·컨텍스트 예산·citation card 계약으로 전달한다.
7. MCP 도구는 명시적 서버 멘션을 우선하고, Context7 자동 제공은 실제 프로그래밍 의도가 확인될 때만 허용한다.

## Rust/WASM 경계

- 자연어 질문과 폴더 이름의 직접·로마자 유사도 판정은 Rust/WASM에서 결정한다.
- scoped 검색 임계치와 Context7 자동 제공 여부도 Rust/WASM의 결정적 정책으로 둔다.
- TypeScript는 Obsidian vault 파일·폴더 수집, RAG 런타임 호출, DOM 렌더링과 결과 매핑만 담당한다.
- vector store의 path prefix 필터는 저장소 I/O 경계로 TypeScript에 둔다.

## 채팅 응답 안전성

- tool call이 하나라도 있으면 reasoning-only 질문 분류보다 tool 실행을 우선한다.
- 모델의 내부 reasoning은 사용자에게 질문 카드로 승격하지 않는다. 사용자에게 필요한 질문은 visible answer content에 있어야 한다.
- 자동 RAG 검색 결과가 없으면 `관련 노트 없음` 상태를 명확히 표시하고, 볼트 근거가 없는 문서명은 기존 source validation 경고로 검증한다.
- 내장 RAG 출처와 MCP 결과는 UI와 데이터 경계에서 별도로 표시한다.

## UI 구조

- 빈 대화에는 `볼트에 대해 물어보세요` 제목, 내장 문서 자동 참조 설명, 실제 동작하는 예시 질문 버튼을 둔다.
- 정상 readiness card는 렌더링하지 않는다. 준비·오류·설정 필요 상태만 compact notice 한 줄로 보여준다.
- readiness 행동은 상태 label을 반복하지 않고 `문서 준비`, `다시 연결`, `모델 선택`처럼 다음 행동을 말한다.
- 정상 MCP 연결 bar는 숨기고 연결 중·부분 실패·실패 때만 표시한다.
- 설정 버튼과 도구 버튼은 문자 기호 대신 Obsidian icon과 접근 가능한 label을 사용한다.
- 전송 전에는 `문서를 자동으로 찾습니다`를, 전송 후에는 실제 관련 노트 수와 citation card를 보여준다.

## 접근성과 반응형

- 빈 상태 예시 질문은 실제 `button`이며 keyboard focus와 visible focus ring을 제공한다.
- readiness는 `role=status`, `aria-live=polite`를 유지하고 진행 상태를 색상 외 텍스트로 전달한다.
- 420px 이하에서는 예시 질문, readiness detail, toolbar가 세로로 재배치되고 긴 경로가 잘린 채 의미를 잃지 않도록 title을 제공한다.
- reduced-motion에서는 기존 공통 motion gate를 따른다.

## 테스트 계약

- 채팅을 열 때 RAG 초기화를 coalesce하고 실패를 UI 상태로 전달한다.
- 전송 직전 RAG가 준비되지 않았으면 자동 초기화 후 context를 검색한다.
- 명시 폴더 멘션이 `.txt` 등 RAG indexable 파일을 포함한다.
- 한글 표기 `네빌`이 최상위 `neville` 폴더 힌트로 계획되고 unrelated folder는 선택하지 않는다.
- path prefix vector 검색은 해당 폴더 entry만 반환하고 cache key를 분리한다.
- tool call이 있는 reasoning-only 응답은 질문 카드로 조기 종료되지 않는다.
- Context7는 프로그래밍 의도 또는 명시 멘션 없이 자동 제공되지 않는다.
- 빈 상태, compact readiness, icon button, 한·영 i18n과 좁은 폭 CSS를 구조 테스트로 고정한다.

## 완료 조건

- 테스트 볼트의 기존 벡터가 채팅에서 별도 설정 조작 없이 사용된다.
- `네빌 고다드는 요한 계시록에 대해서 뭐라고 했어?` 같은 질문이 MCP 없이 `neville`과 관련 성경 노트를 자동 참조한다.
- 출처가 있는 답변은 관련 노트 수와 실제 citation card를 보여주고, 출처가 없으면 없는 상태를 속이지 않는다.
- 빈 채팅에서 사용자가 자동 문서 참조와 다음 행동을 3초 안에 이해한다.
- lint, typecheck, test, security:full, build, review gate와 실제 Obsidian 일반·좁은 폭 스크린샷 검수를 통과한다.
