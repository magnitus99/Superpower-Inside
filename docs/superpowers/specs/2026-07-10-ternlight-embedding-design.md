# Ternlight 기본 임베딩 설계

## 목표

Superpower Inside는 `@ternlight/base`를 API 키와 별도 로컬 서버가 필요 없는 내장 임베딩 옵션으로 항상 제공한다. 신규 설치의 기본값은 Ternlight로 두고, 기존 사용자가 선택한 OpenAI·Ollama·OpenRouter·커스텀 임베딩은 임의로 바꾸지 않는다.

## 배포 결정

Ternlight의 엔진·토크나이저·가중치가 들어 있는 `tern_engine_bg.wasm`은 플러그인 GitHub Release에 별도 자산으로 게시한다. Obsidian 커뮤니티 설치기는 `main.js`, `manifest.json`, `styles.css`만 설치하므로, 플러그인은 Ternlight가 실제로 선택되었을 때 다음 순서로 자산을 준비한다.

1. 플러그인 디렉터리의 기존 WASM 크기와 SHA-256을 검증한다.
2. 유효하면 네트워크 요청 없이 즉시 사용한다.
3. 없거나 손상됐으면 현재 플러그인 버전의 GitHub Release 자산을 한 번 내려받는다.
4. 다운로드 결과의 HTTP 상태, 바이트 크기, SHA-256을 검증한다.
5. 임시 파일에 쓴 뒤 대상 경로로 교체하고 WASM을 초기화한다.

이 방식은 약 10MB 모델을 `main.js`의 Base64 문자열로 중복 인코딩하지 않으면서, 사용자가 별도 설치 단계를 관리하지 않게 한다. 다운로드가 실패하면 기존 원격 임베딩으로 조용히 대체하지 않고 명확한 오류와 다시 시도할 수 있는 기존 연결 테스트 동작을 사용한다.

## 설정 계약

- Ternlight 내장 프로필과 `ternlight-base` 모델은 저장된 프로바이더 프로필 유무와 관계없이 항상 정규화한다.
- 내장 프로필은 활성화 상태이며 API 키와 Base URL을 요구하지 않는다.
- 신규 또는 아직 기본 설정 그대로인 설치는 Ternlight를 선택한다.
- 유효한 기존 임베딩 선택은 그대로 보존한다.
- RAG 모델 선택 목록에는 항상 `Ternlight — ternlight-base`가 표시된다.
- RAG 모델 선택 바로 아래에서 Ternlight의 온디바이스 실행·개인정보 보호·API 키/서버 불필요·필요 시 1회 자동 다운로드를 항상 설명한다.

## 런타임과 오류 처리

- 모델 준비와 WASM 초기화는 동시에 여러 요청이 들어와도 하나의 Promise로 합친다.
- 실패한 초기화 Promise는 초기화 상태에서 제거하여 연결 테스트나 다음 임베딩 요청으로 다시 시도할 수 있게 한다.
- 검증되지 않은 다운로드는 최종 모델 경로에 기록하지 않는다.
- Ternlight는 384차원 벡터를 반환하며 기존 임베딩 배치 검증과 캐시 계약을 그대로 사용한다.
- 모델 변경은 기존 벡터의 provider/model metadata와 불일치하므로 현재 RAG 상태 계산이 재인덱싱 필요 상태로 표시한다.

## 검증

- 기존 프로필이 있는 설정에도 Ternlight 옵션이 추가되고 기존 선택은 유지되는 단위 테스트
- 로컬 자산 재사용, 누락 시 다운로드, 손상 시 교체, 체크섬 불일치 거부, 동시 준비 병합 테스트
- Ternlight 임베딩 384차원 생성 테스트
- lint → typecheck → test → security → build → Obsidian review gate
- `.test-vault`에서 실제 드롭다운 옵션, 설명 카드, 임베딩 생성 테스트와 오류 로그를 확인하고 스크린샷 검수
