# 프로바이더 상세 영역 위계 개선 설계

## 결정

연결 목록의 각 프로바이더 행은 독립된 선택 헤더로 유지하고, 펼쳐진 상세 설정은 해당 행 아래에 종속된 편집 영역으로 표현한다. 상세 영역에는 약한 보조 배경, 왼쪽 연결선, `연결 세부 설정` 문맥 라벨을 적용한다. 별도 카드나 강한 테두리를 추가하지 않는다.

사용자는 디자인 판단과 승인 권한을 작업자에게 위임했다. 이 문서를 구현 계약으로 사용한다.

## 검토한 접근

1. 상세 영역을 독립 카드로 감싸면 경계는 가장 강하지만 카드 속 카드가 되어 설정 UI 계약과 충돌한다.
2. 헤더의 색상과 굵기만 높이면 구현은 작지만 긴 상세 설정을 스크롤할 때 어느 프로바이더에 속하는지 다시 흐려진다.
3. **선택안: 헤더와 상세 영역을 하나의 열린 disclosure 상태로 연결한다.** 열린 헤더에는 선택 상태를 주고, 상세 영역에는 연결선과 문맥 라벨을 둬 종속 관계를 계속 보여준다.

3안을 적용한다.

## 시각 구조

- 접힌 프로바이더는 현재와 같은 평평한 목록 행이다.
- 펼친 프로바이더 헤더는 약한 선택 배경과 강조색 연결선을 사용한다.
- 상세 영역은 헤더와 같은 연결선 축을 이어받고, 최상단에 아이콘과 `연결 세부 설정` 라벨을 표시한다.
- 연결 설정, 일반 모델, 임베딩 모델, 위험 작업은 기존 평평한 row와 구분선을 유지한다.
- 다음 프로바이더 행과의 간격은 목록 내부 리듬만 사용할 뿐 별도 카드 간격으로 만들지 않는다.

## 동작과 접근성

- 동시에 하나만 펼치는 기존 disclosure 동작과 `aria-expanded`, `aria-controls` 계약을 보존한다.
- 문맥 라벨은 장식이 아니라 펼친 영역의 목적을 설명하는 짧은 텍스트로 제공한다.
- 상태는 기존 텍스트 label을 유지하며 색상만으로 전달하지 않는다.
- `focus-visible`에서는 열린 헤더와 무관하게 키보드 포커스 윤곽이 분명해야 한다.
- 520px 이하에서는 연결선의 들여쓰기를 줄이고, 라벨·긴 URL·모델명이 가로 overflow 없이 줄바꿈된다.
- reduced-motion에서는 기존 disclosure 아이콘 회전 transition을 제거한다.

## 변경 범위

- `src/settings.ts`: 프로바이더 disclosure 상세 영역에 문맥 헤더를 추가한다.
- `src/i18n.ts`: 한국어·영어 문맥 라벨을 추가한다.
- `styles.css`: 열린 헤더, 연결선, 상세 배경, 좁은 폭, reduced-motion 스타일을 추가한다.
- `src/settings-redesign.test.ts`: 구조, i18n, 반응형·모션 계약을 고정한다.

설정 스키마, 저장, provider transport, 모델 검증, Rust/WASM 경계는 변경하지 않는다.

## 검증

1. 구조 테스트를 먼저 실패시키고 구현 후 통과시킨다.
2. 린트, 타입체크, 전체 테스트를 순서대로 통과시킨다.
3. `npm run security:full`, `npm run build`, manifest 버전 기반 Obsidian review gate를 통과시킨다.
4. 마지막에 실제 `.test-vault` Obsidian 화면에서 접힌 프로바이더, 펼친 프로바이더, 다음 프로바이더와의 경계, 좁은 폭을 스크린샷으로 확인한다.

## 완료 조건

- 프로바이더 행과 그 상세 설정의 소유 관계가 한눈에 구분된다.
- 중첩 카드 없이 기존 작업 중심 설정 디자인 계약을 유지한다.
- 기존 프로바이더 기능에 회귀가 없고 자동 검증과 실제 화면 검수를 모두 통과한다.
