# Superpower Inside 제품 철학

## 핵심 가치

**사용자가 자신의 자료에서 근거를 찾고, 의미를 이해하고, 다음 작업에 활용하는 흐름을 끊김 없이 이어 준다.**

제품의 가치는 기능의 개수보다 기능이 연결되어 완성하는 작업에 있다. 검색이 좋은 자료를 찾아도 답변에서 활용하지 못하면 흐름은 끝나지 않는다. 답변이 유용해도 근거를 확인할 수 없으면 판단에 쓰기 어렵다. 초안이 만들어져도 사용자가 다시 맥락을 설명해야 한다면 앞선 작업의 가치를 충분히 이어받지 못한 것이다.

우리가 지향하는 편안함은 사용자가 내부 구조를 관리하지 않아도 자신의 작업에 집중할 수 있는 상태다. 제품은 필요한 준비를 맡고, 사용자는 질문·판단·결과 활용에 집중한다. 이러한 편안함은 정확한 상태 설명, 자료 보존, 사용자의 결정권을 전제로 한다.

## 사용자와 가치

주 사용자는 Obsidian에 축적한 노트와 문서로 조사·학습·비교·집필하는 사람이다. 자료를 많이 모으는 것보다 이미 모은 자료를 이해하고 다시 활용하는 데 도움을 제공한다.

사용자는 자신의 자료로 질문을 시작하고, 관련 근거를 확인하고, 답변을 검토한 뒤 다음 질문이나 초안으로 이어 갈 수 있어야 한다. 숙련 사용자를 위한 제어는 제공하되, 일반적인 작업을 끝내기 위해 검색 방식·인덱스·도구 연결의 내부 구조를 먼저 배우게 하지 않는다.

무료·오픈소스를 유지한다. 플러그인의 무료 제공과 외부 제공자의 비용·가입 조건은 명확히 구분한다.

## 전반적인 제품 흐름

제품의 기본 흐름은 **작업 시작 → 자료 확보 → 이해와 비교 → 근거 확인 → 결과 활용**이다. 사용자는 필요에 따라 앞 단계로 돌아가거나 일부 단계를 건너뛸 수 있다. 이 흐름을 고정된 마법사나 필수 클릭 순서로 만들지는 않는다.

| 단계 | 사용자가 얻어야 하는 것 | 다음 단계에 전달해야 하는 것 |
| --- | --- | --- |
| 작업 시작 | 무엇을 묻고 어떤 자료를 사용할지 정할 수 있는 진입점 | 질문의 목적과 선택한 자료 범위 |
| 자료 확보 | 관련 노트와 지원 문서에서 작업에 필요한 내용 | 본문 맥락과 원문으로 돌아갈 출처 정보 |
| 이해와 비교 | 질문에 맞는 설명, 주장 간 차이, 자료에 드러난 관계 | 결론의 근거와 아직 확인되지 않은 부분 |
| 근거 확인 | 답변의 출처를 열고 판단을 검토할 수 있는 경로 | 확인된 내용과 수정하거나 보충할 쟁점 |
| 결과 활용 | 다음 질문, 개요, 초안 등 현재 작업에 쓸 수 있는 결과 | 이어서 작업할 맥락과 사용자의 선택 |

단계가 바뀔 때 질문의 목적, 자료 범위, 출처, 사용자의 입력을 불필요하게 잃지 않는다. 이미 제공한 정보를 다시 입력하게 하거나 같은 자료를 반복해서 찾아 붙이게 한다면 연결 방식부터 개선한다.

설정·준비·연결·복구는 이 흐름을 지원한다. 사용자가 반드시 결정해야 하는 사항이 있을 때만 일상 작업의 전면에 나타난다.

## 기능 간 시너지

시너지는 한 기능의 결과가 다음 기능의 입력으로 쓰여 **사용자의 반복 작업을 줄이고 결과의 활용 가능성을 높이는 것**이다. 기능을 같은 화면에 배치하는 것만으로 시너지가 생기지는 않는다.

- 자료 선택과 검색은 질문에 필요한 범위를 함께 좁힌다. 문서 추출은 지원 형식을 넓히면서 본문과 출처의 연결을 유지한다.
- 검색과 문맥 읽기는 찾은 구절이 어떤 의미인지 이해할 근거를 제공한다. 관계 탐색은 질문에 필요한 경우 자료 사이의 연결을 보충한다.
- 답변과 출처 확인은 설명을 검토 가능한 결과로 만든다. 비교는 공통점뿐 아니라 충돌과 자료 부족도 드러내야 한다.
- 후속 질문과 초안 작성은 앞서 확보한 맥락을 이어받아 사용자가 같은 배경을 다시 설명하는 일을 줄인다.
- 외부 도구는 기본 흐름만으로 해결되지 않는 작업을 보완한다. 연결 자체를 제품 가치로 내세우거나 불필요한 호출을 늘리지 않는다.

새 기능이나 변경은 어느 단계의 문제를 해결하는지, 앞 단계에서 무엇을 받는지, 다음 단계에 무엇을 남기는지 설명할 수 있어야 한다. 연결되지 않는 기능은 독립적으로 유용한 이유를 입증하거나 범위를 줄인다.

## 조용하고 신뢰할 수 있는 동작

안전한 기본값, 자동 감지, 기존 설정 재사용을 먼저 검토한다. 새 설정은 사용자가 결과에 영향을 주는 의미 있는 선택을 해야 할 때 추가한다. 자동화 가능한 준비를 반복적인 사용자 관리 업무로 넘기지 않는다.

자동화는 실패를 숨기는 방식으로 구현하지 않는다. 실제 완료와 준비 중인 상태를 구분하고, 복구 가능한 실패는 사용자의 입력과 맥락을 보존한 채 해결할 수 있어야 한다. 초기화·재색인 같은 큰 복구 작업은 일반적인 사용법이 아니라 필요한 상황의 해결 수단이다.

사실·추론·자료 부족을 구분한다. 출처가 있다는 이유만으로 답변의 정확성을 보장하지 않는다. 기본 볼트 도구의 읽기 전용 경계와 외부 도구의 승인·취소 경계를 유지한다. 로컬 처리와 외부 전송, 실제 중단과 최선의 취소 시도를 구분해서 설명한다.

## 문구: 왜 보여 주는가

각 문구는 사용자가 **상태를 이해하거나, 선택하거나, 행동하거나, 결과를 확인하는 데** 기여해야 한다. 어떤 단계에서 어떤 판단을 돕는지 설명할 수 없는 문구는 줄이거나 진단 영역으로 옮긴다.

행동이 필요하면 원인과 가장 작은 다음 행동을 제시한다. 행동이 필요 없는 정상 상태는 반복 알림으로 주의를 빼앗지 않는다. 비용·자료 전송·실패·취소의 중요한 한계는 판단이 필요한 위치에서 알 수 있어야 한다.

내부 용어는 사용자의 선택에 필요한 경우에만 설명과 함께 사용한다. 버튼·상태·답변이 같은 동작을 서로 다른 말로 부르지 않게 한다. 영어와 한국어는 약속의 범위와 한계를 동일하게 전달한다.

## 버튼: 왜 그렇게 작동하는가

버튼은 현재 작업을 다음 상태로 옮기는 행동이다. 이름이 약속하는 결과와 실제 효과가 일치해야 한다. 저장·연결·검색 등 관련 호출과 부작용까지 확인하며, 보기 전환이 재연결이나 재색인을 일으킨다면 그 필요성을 설명할 수 있어야 한다.

각 행동은 시작 조건, 진행 상태, 중복 실행 방지, 성공 조건, 실패 후 복구, 취소 범위를 명확히 한다. 오래된 응답이 최신 결과를 덮지 않게 하고 입력·자료·포커스를 불필요하게 잃지 않게 한다. 재시도는 이미 끝낸 작업을 가능한 범위에서 보존한다.

작업 단위의 주 행동은 분명하게 정리하되 필수 제어를 숨기지 않는다. 버튼을 추가하기 전에 기존 행동과 자동 처리로 해결할 수 있는지 확인한다. 판단 기준은 버튼의 외형이 아니라 사용자의 의도, 실제 효과, 다음 단계와의 연결이다.

## README: 왜 그 단어인가

README는 대상 사용자가 **어떤 작업을 할 수 있고, 기능들이 어떻게 연결되며, 어떤 조건과 한계가 있는지** 이해하게 해야 한다. 첫 설명과 주요 예시는 전체 사용 흐름을 전달한다. 기술 이름을 나열하는 것으로 제품 가치를 대신하지 않는다.

글자·단어·문장마다 정확성, 독자의 이해, 문맥상의 필요를 검토한다. “자동”, “무료”, “로컬”, “안전”, “지원” 같은 단어는 적용 범위와 예외를 확인한다. 근거 없는 보장·비교·수식어는 제거한다. 전문 용어는 독자가 기능을 이해하거나 선택하는 데 필요한 경우 사용한다.

기능 설명은 현재 구현과 확인된 동작에 근거한다. 설치 조건, 제공자 비용, 추출 한계, 결과 검토에 필요한 사항을 찾을 수 있어야 한다. 영어와 한국어는 같은 사용자 가치와 제약을 설명한다.

단어 수정은 해당 문맥에서, 가치 제안 수정은 문단과 사용 흐름 전체에서 판단한다. 변경 없는 모든 단어에 별도 보고서를 만들 필요는 없다.

## 판단 기준과 경계

제품 결정은 다음 질문으로 검토한다.

1. 사용자의 어떤 작업을 완성하는 데 필요한가?
2. 앞 단계의 맥락을 무엇까지 이어받고, 다음 단계에 무엇을 전달하는가?
3. 사용자의 반복 입력·판단 부담·관리 작업을 무엇이 줄이는가?
4. 자료 보존·근거 확인·사용자 통제에 어떤 영향을 주는가?
5. 약속한 효과를 현재 구현·호출부·테스트 또는 실제 동작으로 확인할 수 있는가?

편안함과 투명성이 충돌하면 자료 보존, 사실에 맞는 설명, 사용자의 결정권을 우선한다. 화면 구성과 시각 검수는 `design.md`, 작업 절차와 수동 검사 실행은 `AGENTS.md`, 현재 기능과 사용 안내는 `README.md`가 담당한다.

이 문서는 2026년 과거 커밋 `fd090e606ef094aebeb83acda3d675ed5e0a4c63`의 제품 철학을 바탕으로 제품 결정의 이유와 기준을 정리한 로컬 문서다. 목표로 하는 경험을 정의하며, 현재 구현이 모든 기준을 충족한다는 보증은 아니다.
