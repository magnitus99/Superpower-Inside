# 선행 원칙을 보는 보완 관점

**승인 문장과 조건은 유지한다.** 중복 후보를 새 원칙으로 늘리지 않고, 기존 원칙을 다른 각도에서 이해하는 데 필요한 근거만 연결한다. 사용자 요청일은 2026-10-13이다. 이 자료는 구현 변경이나 철학 검토 실행의 승인이 아니다.

## 1. P07에서 보강한 개인별 설정 관점 → P01

**기존 원칙:** 기존 의도·맥락·설정·권한 안에서 가능한 일을 제품이 맡는다.

**추가하는 관점:** 같은 흐름이라도 이미 선택한 임베딩·프롬프트 설정에 따라 사용자가 기대하는 처리 조건이 다를 수 있다. 그 선택이 실제 작업에 이어져야 설정한 일을 다시 챙길 부담이 줄어든다. 새 개인화 기능을 만들자는 뜻은 아니다.

**외부 근거:** Obsidian의 Malleable 원칙(SW01)은 사용자 방식에 맞춰 도구를 조정할 수 있는 가치를 설명한다. 이는 설정을 통해 자신에게 맞는 도구를 구성하는 보조 사례이며 AI가 자동으로 취향을 알아낸다는 증거는 아니다. [공식 원문](https://obsidian.md/about)

**현재 구현 근거:** [prompt-library.ts](../../src/chat/prompt-library.ts)의 `getEffectiveSystemPrompt()`는 세션 지침·선택된 프롬프트·기존 설정을 해석한다. [main.ts](../../main.ts)는 선택된 임베딩 설정을 런타임 구성에 사용한다. 이 코드를 읽은 사실은 개별 설정의 실제 결과 품질을 실행 검증했다는 뜻이 아니다.

**보강 범위:** 기존 설정 재사용이라는 규칙은 이미 P01에 있으므로 반복하지 않는다. 개인별로 정한 조건이 질문→자료 처리→결과로 이어지는지 보는 이유와 출처만 보강한다. Bespoke는 별도 독립 철학으로 추가하지 않는다.

## 2. P08에서 보강한 시간과 재사용 관점 → P01·기존 보존 계약

**기존 원칙:** 맥락과 근거를 이어 주고 기존 작업을 보존한다. 자료·설정·세션 보존과 저장 호환은 현행 작업 계약이다.

**추가하는 관점:** 편안함은 현재 클릭 수만이 아니라 나중에 다시 사용할 때의 재작업 부담에도 나타난다. 저장된 작업이 어떤 자료와 판단에 기반했는지 다시 활용할 수 있어야 앞선 작업의 가치가 이어진다.

**외부 근거:** Obsidian의 Durable 원칙(SW01)은 개방된 형식과 장기 자료 보존을 강조한다. Ink & Switch의 local-first 연구(RS02)는 축적한 작업의 소유·보존과 다시 사용할 수 있는 능력을 함께 다룬다. [Obsidian](https://obsidian.md/about), [Ink & Switch](https://www.inkandswitch.com/essay/local-first/)

**현재 계약 근거:** [루트 AGENTS.md](../../AGENTS.md)와 [채팅 AGENTS.md](../../src/chat/AGENTS.md)는 자료·설정·세션 보존과 legacy load·round-trip을 요구한다. [persistence.ts](../../src/chat/persistence.ts)는 세션 저장·복원 연결 지점이다.

**보강 범위:** 새로운 저장 형식, 무기한 호환 보장, 모든 AI 동작의 오프라인 제공을 약속하지 않는다. 이미 있는 보존 조건을 다시 추가하지 않고, 시간에 따른 재작업 감소라는 고객 가치와 출처를 연결한다.

## 3. 시선과 맥락 전환 관점 → K01·P01·P04·P09

**사용자 지정 관점:** 디자인과 사용자 시선 흐름까지 살펴 불필요한 부담을 줄인다.

**추가하는 관점:** 클릭이나 입력이 적어도 필요한 정보의 위치를 반복해서 찾거나, 화면을 옮길 때마다 원래 목적을 떠올려야 하면 사용자의 부담이 남는다. 기능 연결의 효과는 눈과 주의의 흐름에서도 살핀다.

**외부 보조 사례:** Scrivener(SW10)는 작성 중인 글 곁에서 참고 자료를 확인하는 흐름을 제공한다. 자료를 확인하러 갔다가 돌아오는 작업을 줄이는 사례로 참고한다. 이 사례가 우리 화면의 특정 배치를 정당화하거나 실제 시선 이동 감소를 측정한 증거는 아니다. [공식 원문](https://www.literatureandlatte.com/scrivener/overview)

**관찰 질문:**

- 지금 필요한 상태·결과·다음 행동을 찾기 위해 어디를 다시 보게 되는가?
- 근거를 확인하고 돌아온 뒤 같은 질문·자료 범위·읽던 위치를 다시 파악해야 하는가?
- 정보가 나타나거나 바뀔 때 사용자의 읽는 흐름을 끊는가?
- 문구·버튼·화면 전환을 바꿨을 때 실제 목적을 완료하는 부담이 줄어드는가?

**범위:** 이 질문은 제품 철학의 판단 이유를 보완한다. 배치·정보 위계·모션·접근성의 실제 기준은 [design.md](../../design.md)를 유지한다. 화면마다 정답 배치나 시선 횟수 임계값을 만들지 않는다. 실제 화면 관찰은 해당 작업을 할 때 수행하며 이번 문서 작업에서는 실행하지 않았다.

## 4. 중복해서 추가하지 않은 것

| 후보 | 이미 포함된 선행 기준 | 처리 |
| --- | --- | --- |
| P03·P06 | P01의 반복 업무 자동화·맥락과 근거 연결 | 같은 조건을 다시 추가하지 않음 |
| P10 | P02·기존 README와 Patina의 실제 범위 설명 | 같은 정확성 조건을 다시 추가하지 않음 |
| P11 | P01·P04의 작업 보존·실패 후 안내 | 같은 복구 조건을 다시 추가하지 않음 |
| P12 | K01·P01·P04의 목적 중심 진입과 주의 배분 | 시선 관점의 관찰 질문만 연결 |
| P13 | P01·기존 자료 소유·전송·승인 계약 | 같은 통제 조건을 다시 추가하지 않음 |
| P14 | P01의 결정권·P09의 사용 만족·기존 숙련 제어 | 새 숙련 기능이나 강제 조작을 추가하지 않음 |
| P15 | P05·P02의 전체 경험 개선과 충실도 유지 | RR03 근거가 P05에 이미 있어 다시 추가하지 않음 |

이는 별도의 사용자 승인으로 세지 않는다. 각 후보의 선행 연결과 분류는 [결정 데이터](../decisions/status.json)에 기록했다. 근거 보강을 이유로 승인된 방향이나 조건을 확대하지 않는다.
