# 확정 방향과 승인 기록

이 문서는 당시 승인 문장·조건·응답을 보존하는 근거 자료이며 현행 구현 지시나 철학 검토 실행 권한이 아니다. 현재 기준은 [제품 철학 스펙](../../product-philosophy.md), P16 수단·속도 목표의 적용 시점은 그 문서의 구분 절과 [검색 품질 스펙](../../search-quality.md)을 따른다. 로컬 대화 식별자와 구체 검색어 예시는 공개본에서 제외했으며 승인 상태·조건의 의미는 바꾸지 않았다.

**사용자 지정 핵심 방향 3개, 승인 항목 5개.** P01·P04·P05·P09는 제품 방향이며 P02는 기본 품질 조건이다.

- K01: 매우 심플함
- K02: 보이지 않는 노력 (영국 귀족)
- K03: 신경쓰지 않아도 "알아서"

## P01 · 최소한의 관여로 목적을 이룬다

**승인 문장:** 제품은 사용자의 의도와 기존 맥락·설정·권한을 바탕으로 자동화할 수 있는 판단과 작업을 최대한 맡아, 최소한의 관여로 목적을 이루게 한다. 목적 표현·자료 선택·결과 검토도 고정된 수작업으로 남기지 않는다. 제품이 처리할 근거가 부족하거나 사용자의 결정이 반드시 필요한 지점에서만 관여를 요청한다. 준비부터 결과 활용까지 맥락과 근거를 연결하고 실패 시 기존 작업을 보존한다.

**사용자 응답:** 다 좋아. 다 좋은데 우리는 아무래도 ai와 매우 밀접한 디지털 제품이야. 사용자가 맡는 일의 경우 최대한 자동화가 가능한 부분은 자동화 시켜야 해. 말 그대로 롤스로이스 핸들을 손가락 하나만 움직여도 되는 수준이면 좋겠지. 이걸로 idealisation 하면 좋겠지만 그 범위는 여기에 포함되지 않아.

**승인 조건:**

- 사용자의 역할을 목적 입력·자료 선택·결과 검토의 고정 수작업으로 정의하지 않는다. 기존 의도·맥락·설정·권한으로 처리 가능한 부분은 최대한 자동화한다.
- 사용자의 의도나 필요한 결정의 근거가 부족하면 관여를 요청하되 제품이 먼저 확인·처리할 수 있는 일을 떠넘기지 않는다. 기존 권한·자료 보존 계약은 유지한다.
- 손가락 하나만 움직이는 수준은 최소한의 관여를 설명하는 사용자 지정 지향점이다. 실제 차량 성능의 주장이나 자동화 기능의 확정 명세가 아니다.
- 이번 범위는 철학 문장과 책임 범위의 수정·기록이다. idealisation과 구체적인 자동화 기능 구상·구현은 포함하지 않는다.

**승인 조건:**

- 유용한 결과와 편안한 흐름이 정돈됨·세심함을 느끼는 사용 만족으로 이어지는 것을 고객 가치로 삼는다.
- 구체적인 장식·모션·새 기능의 승인으로 확대하지 않으며 기존 디자인 기준과 승인 조건을 유지한다.

### 2026-10-18 · 제품 철학 검토 실행 방식

사용자가 제품 철학 검토를 게이트웨이나 자동 명령 없이 별도로 동작하는 서브에이전트로 두고, 지목해 실행하며, 제1역할을 검토 후 지적·권고로 지정하라고 요청했다. 이어서 npm 검사 명령(자동화)을 삭제하고, 자동화 대상이 아니며 검토 범위 지정과 수정 승인이 필요하다고 확정했다. 실행 방식은 사용자가 범위를 지정해 지목하는 프로젝트 스코프 커스텀 에이전트 `philosophy_reviewer`(`.codex/agents/philosophy-reviewer.toml`) 단독이며, `philosophy:check` npm 스크립트와 검사 스크립트는 제거한다. 기존 P16 승인 방향·조건과 승인 건수는 변경하지 않는다. 기술 근거는 OpenAI 공식 Subagents 문서(커스텀 에이전트 위치 `.codex/agents/`, 필수 필드 `name`·`description`·`developer_instructions`, 직접 요청으로 스폰)다.

**2026-10-18 검토 보조 데모 추가:** 사용자가 철학 검토가 제안에 대해 `design_specialist`를 활용하고 데모를 제작할 수 있으며, 거절 시 데모를 삭제하거나 다시 만들고, 승인된 제품 구현이 검증되면 데모를 삭제한다고 정했다. 승인 원칙·승인 건수는 변경하지 않는다.

### 2026-10-18 · 전수 검토의 수단과 품질 하한 확정(재승인)

philosophy_reviewer 1차 검토가 남긴 blocker 3건(전수 검토의 판단 해석, 커버리지 표기, 실패 처리)에 대해 사용자가 재검토를 승인하고 다음 정의를 확정했다. 이로써 2026-10-17 구체화의 전체 검토·판단은 다음 수단과 하한으로 재승인된다. 최초 승인(2026-10-16)의 나머지 조건과 승인 건수는 변경하지 않는다.

**사용자 확정 정의(원문 취지):** ① 핵심 목표는 병목 제거다 — 최대한 빠르게 답변해야 한다. ② 볼트의 모든 문서를 대상으로 충분히 검토하되, 그 수단은 RAG embedding + BM25 + 지금 구현할 스크리닝 코드(결정적 로컬 계산)다. ③ 전수 검토·판단의 실질 의미 = 품질 하한 보장: 답변이 특정 키워드로 검색해 나온 아무 문서를 읽고 답한 것보다 절대 나쁘면 안 된다. ④ 이 정의를 철학 승인 기록·계약 문서에 반영한다.

**파이프라인 규칙 — 재검토 확정:**
- 하한: 검색(임베딩+BM25+구조 그래프)이 지목한 세그먼트는 점수와 무관하게 전부 LLM 판정 대상에 강제 포함한다.
- 확장: 결정적 스크리닝(어휘/스코어)이 검색이 놓친 대상을 상위부터 추가 판정한다. 전 문서는 스크리닝 점수를 받고 검수 완료로 기록된다.
- 속도: 전 문서 LLM 판정을 제거한다. LLM은 후보 상위만 2단계(경량 screen 대배치 → extract 통과분만)로 수행한다.
- 실패: 스크리닝·screen·extract 실패는 전부 미판정·미완료 고지로 수렴한다(제외로 접지 않는다).
- 표기: 색인 N개 스크리닝 완료 · 검색 하한 포함 · 기계 제외 X(모델 판단 없음) · LLM 채택 A/제외 R · 미판정 U · 읽기 실패 F 계열로 3계층을 분리한다.

**재검토 결과:** blocker 3건은 이 확정으로 해소됐다(해석=재승인 완료, 표기=3계층 확정, 실패=미판정 수렴 확정). 잔여 위험은 하한 충족의 실제 검증(같은 질문·자료·모델·설정 비교), screen 거짓 음성의 추적, 배치 확대 시 응답 완전성이다. 계약 문서(src/chat/AGENTS.md) 반영과 i18n 구현은 제품 구현 단계의 선행 작업이며, 이번 문서 반영은 승인 기록·탐색표·현재 기준까지다.
